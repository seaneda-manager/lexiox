# 문법 설명 페이지 포맷 기준서 (초안)

기준 자료: 사용자가 준 예시 PDF(`문법설명example.pdf`, 교과서 "핵심 문법" 2개 항목: ① it ~ to부정사, ② call A B). 이 포맷을 **개념 1개 = 이 구성의 한 페이지 + 연습문제**로 만든다. 레벨(L1~L5)은 이 틀 안에서 문체·예문 길이·분량만 바꾼다.

## 1. 한 항목의 구성 (위에서 아래로)

| # | 블록 | 예시 PDF에서 | 내용 규칙 |
|---|---|---|---|
| A | **제목 줄** | `① it ~ to부정사`, `② call A B` | 개념 표시명. 기호(~, A B)로 구조를 드러낸다. |
| B | **도입 박스** | Reading(교과서 본문 문장 1개, 핵심 부분 밑줄·품사 표시) + Grammar(짧은 예문 3개, 핵심 굵게, 오른쪽에 한글 번역) | 문장은 짧고 포인트 하나. 굵게 = 이 개념이 적용된 부분. |
| C | **설명 문단** | "문장의 주어로 쓰인 to부정사(구)가 … '~하는 것은 …하다'라고 해석한다." | 한국어 한 문단. 정의 → 해석법 → 변환 예(원문 → 변환문, `→`로 연결). |
| D | **번호 규칙 ❶❷…** | `❶ 형태: 「it + be동사 + 형용사/명사 + to부정사(구)~」`, `❷ to부정사의 부정` | 규칙 하나당 공식 한 줄 + 예문 3~5개. 예문 = 영어 + (한글 번역 괄호). 핵심 부분 굵게. |
| E | **참고 / 표** | `참고 「it ~ that절」`, call/make/name/elect/find/consider 표(동사 + 구조 ↔ 뜻) | 동사·구조가 여러 개이면 표로 나란히. |
| F | **시험 출제 박스** (오른쪽 여백) | "to부정사구 주어가 쓰인 문장을 가주어 it으로 전환하는 문제…" | 내신에서 이 개념이 어떻게 출제되는지 1~2문장. |
| G | **1등급 비법 박스** | "비인칭 주어 it과 가주어 it을 구별해야 한다" | 학생이 자주 틀리는 구별·함정 1~2문장 + 짧은 예. |
| H | **Plus Point** | ① 의미상 주어 for+목적격 / ② of+목적격 | 심화 규칙 1~3개. 규칙 설명 + 예문 1~2개. |
| I | **연습문제** | 01 다시 쓰기(…로 시작하여), 02 배열(괄호 단어 순서대로), 02 어법 고치기(밑줄 친 문장에서 틀린 곳 찾아 고쳐 쓰기), 교과서 쪽수 표시, 정답은 뒤집어 인쇄 | 아래 3절의 문제 유형. |

## 2. 현재 데이터 구조와의 대응

| 블록 | 현재 `GrammarLesson` | 상태 |
|---|---|---|
| A 제목 | `explanation.titleKo`, `topic` | 있음 |
| B 도입 박스 | `explanation.examples`(짧은 예문) | **부분** — Reading 문장(교과서 출처) + 굵게 표시 + 품사 라벨이 없음 |
| C 설명 문단 | `explanation.summaryKo` | 있음(문단 1개) |
| D 번호 규칙 | `explanation.rules` + `exampleGroups` | **부분** — 규칙과 그 규칙의 예문이 분리돼 있어 "규칙 → 공식 → 예문" 한 덩어리가 아님 |
| E 표 | 없음 | **없음** |
| F 시험 출제 | 없음 | **없음** |
| G 1등급 비법 | 없음 | **없음** |
| H Plus Point | 없음 | **없음** |
| I 연습문제 | `blanks`, `drillFill`, `drillFix`, `questions` | **부분** — 다시 쓰기, 단어 배열, 어법 고쳐 쓰기(서술형)가 없음 |

## 3. 문제 유형 (예시 PDF 기준 추가 후보)
- **다시 쓰기**(rewrite): 주어진 문장을 지시대로 전환. 정답 여러 개 허용. (`It ___`처럼 시작어 제시)
- **배열 영작**(order): 한글 뜻 + 괄호 단어들을 순서대로 배열. 불필요 단어 없음.
- **어법 고쳐 쓰기**(fix_write): 문장에서 틀린 곳을 찾아 바르게 고쳐 문장 전체를 다시 쓰기. (현재 `drillFix`는 한 단어만 고침)
- 기존: 빈칸 채우기, 틀린 곳 고치기+이유, 객관식 4유형은 유지.
- 정답은 별도 표기(학생에게는 제출 후 공개).

## 4. 레벨별로 바뀌는 것 (이 틀 안에서)
- **C 설명 문단**: L1 쉬운 한국어·용어 최소 → L5 영어 용어·예외 포함.
- **B/D 예문 길이**: LEVEL_SPEC(4~7 / 6~9 / 8~12 / 12~16 / 15+ 단어).
- **D 규칙 수**: 낮은 레벨은 핵심 규칙만, 높은 레벨은 전부.
- **F/G/H**: L1~L2는 생략 또는 짧게, L3 이상에서 본격 사용.
- **I 문제**: 레벨 정의표(형태 확인 → 서술형·지문 어법)대로 유형 비중 조정.

## 5. 문체 규칙 (예시에서 읽은 것)
- 설명은 "~한다/~이다"체. 번역은 괄호 안에 자연스러운 한국어.
- 공식은 「 」로 감싸고, 예문의 핵심 부분은 굵게. 변환은 `→`.
- 구별해야 할 것은 같은 틀에서 나란히(예: 가주어 it vs 비인칭 주어 it).
- 한 예문 한 포인트. 교과서 본문 표현은 B 박스 Reading에 인용(출처 쪽수 표시).
- 저작권: 예시 PDF의 문장을 그대로 베끼지 않는다. 구성과 방식만 따르고 문장은 새로 쓴다.

## 5-B. 서식 규칙 — 들여쓰기와 기호

**원칙: 기호와 번호는 데이터에 쓰지 않고 화면이 구조에서 붙인다.** AI가 `❶`, `•`, `1.` 같은 기호를 글자로 쓰면 항목마다 제각각이 되고, 나중에 화면 디자인을 바꿀 때 전부 고쳐야 한다. 구조(배열의 순서, 필드 종류)가 곧 기호다.

| 위계 | 화면에 붙는 기호 | 데이터에서는 | 들여쓰기 |
|---|---|---|---|
| 개념 제목 | `①` `②` (큰 번호) | `topic` (번호는 화면이) | 0 |
| 규칙 | `❶` `❷` `❸` (채운 원 숫자) | `explanation.rules[]` 한 항목 = 규칙 하나 (순서가 번호) | 0 |
| 규칙의 예문 | `•` | 그 규칙의 예문 배열 (영어 + 괄호 번역은 화면이) | 1단계 |
| 심화·참고 내부 번호 | `①` `②` (빈 원 숫자) | 심화 항목 배열의 순서 | 0 (박스 안) |
| 박스 라벨 | `참고` `기출 유형` `1등급 포인트` `심화` (라벨 박스) | 필드 이름이 라벨 | 박스 |
| 틀린 예 | `✗` | `wrong: true` | 1단계 |

- 들여쓰기는 **최대 2단계**(규칙 → 예문). 3단계(예문 아래 설명 아래 …)를 만들지 않는다. 더 필요하면 규칙을 나눈다.
- **글 속에 직접 쓰는 기호**(데이터 안에 글자로 허용): `[b]굵게[/b]`(핵심 부분), `「 」`(공식 틀), `→`(변환·고친 결과), `~`(생략·자리 표시). 이 4개만 쓴다. 그 외 기호(`•`, `-`, `1.`, `①`, `★`, 이모지)는 쓰지 않는다.
- **마크다운은 쓰지 않는다**(`##`, `**`, 백틱, 줄머리 `-` `*`). 화면에 그대로 보이면 AI가 쓴 티가 난다. 붙여넣을 때 자동으로 지우고(`**x**`는 `[b]x[/b]`로 변환), 학생 화면은 `[b]`만 해석한다.
- **번역은 괄호에 쓰지 않는다.** 영어는 `en`, 번역은 `ko` 필드에 따로 쓰고, 화면이 괄호로 붙인다.
- 한 줄에는 한 가지 내용만. 문단을 이어 쓰지 말고 항목을 나눈다. (설명 문단 `summaryKo`만 1~3문장 문단 허용)
- 깜지(`cramText`)는 학생이 그대로 따라 쓰는 글이므로 기호 없이 규칙 하나를 한 줄로, 규칙 사이는 빈 줄 하나.
- 영어 용어는 `[b]to부정사[/b]`처럼 굵게, 한국어 조사는 굵게 바깥에 붙인다.

## 6. 확정된 결정 (사용자, 이 문서가 우선)
1. **한 페이지에 한꺼번에 보여 주지 않는다.** 1절의 블록들은 *강의*로 전달한다. 강의 = 음성 + 판서(요소가 순서대로 흩뿌려지며 나타남)로, 기존 grammar-2026 강의(`text`/`board`/`blank` 세그먼트 + 대본 TTS)와 같은 방식. 강의가 끝나면 방금 나온 내용이 **1페이지 요약**처럼 한 화면에 모여 보인다.
2. **이름 변경**: 시험 출제 → **기출 유형**, 1등급 비법 → **1등급 포인트**.
3. **Plus Point는 이름을 쓰지 않는다.** 낮은 레벨에서는 **심화**(선택 블록), 높은 레벨에서는 그냥 설명의 일부로 둔다.
4. 학생 흐름: **강의(음성+판서) → 요약 1페이지 → 팝업 퀴즈(강의 내용으로) → Drill → 실전 문제 → 서술형**.
5. **팝업 퀴즈 규칙** = 별도 세션이 만든 문법 관문 퀴즈(브랜치 `claude/friendly-goodall-succd3`, 커밋 `23e7796`)와 동일하게 간다: 주관식 먼저 → 틀리면 같은 빈칸이 객관식 → 객관식도 틀리면 정답을 보여 주고 직접 다시 쓰기(감점). 정답이 여러 개(`answers`)와 오답 보기(`options`)를 허용. 데이터는 그쪽 `BlankSegmentContent`(`prompt`, `answer`, `answers?`, `options?`, `hint_ko?`)를 그대로 쓴다. 출제 기준: 주요 포인트, 단락 직후, 챕터당 4~8개, 문장당 1개, 오답 보기 2~3개. ⚠️ 그 브랜치는 아직 `main`에 병합·배포 전.
6. Drill, 실전 문제(객관식 4유형)는 기존 방식 유지. 서술형(다시 쓰기·배열 영작·어법 고쳐 쓰기)은 마지막 단계로 추가.

## 7. 아직 정해지지 않은 것
- 기출 유형·1등급 포인트를 개념 공통 내용만 넣을지(교재/학교별 내용은 나중).
- Reading 박스의 "교과서 문장"을 예시 문장으로 대체할지.
- 서술형 채점: 정답 여러 개 허용 규칙, 1차 자동 채점 범위.
