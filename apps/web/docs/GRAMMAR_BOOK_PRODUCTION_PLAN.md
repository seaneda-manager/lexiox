# 문법 콘텐츠 제작 계획 — "출판하는 책 만들듯이"

대상: 개념 72개 × 레벨 L1~L5 (필수 약 215칸). 목표: 학생에게 나가는 모든 칸이 **기준서를 지키고, 자동 점검과 별도 검수와 시험 사용을 거친** 것만 `final`이 되게 한다.
원칙: **사실(규칙)은 한 번만 정하고, 레벨은 표현만 바꾼다.** 칸을 낱개로 만들지 않고 개념 단위로 만든다.

## 1. 공정 (출판 공정에 빗댐)

| 단계 | 출판 | 여기서는 | 산출물 | 담당 |
|---|---|---|---|---|
| 0 | 편집 기준서 | 문체·용어·예문·번역·문항 규칙 확정 | `GRAMMAR_STYLE_GUIDE.md` | 사용자 확정 + 초안 Claude |
| 1 | 기획 | 개념별 **명세서**(핵심 규칙 세트·커버리지 표·대비 개념·흔한 오류·교재 단원) | 개념당 1건, 레벨 무관 | Claude 초안 → 사용자 확인 |
| 2 | 원고 | 레벨별 4섹션(설명+예문 / 깜지+빈칸 / Drill / 문제) | 칸당 JSON | Claude(구독 한도 내) 또는 외부 AI |
| 3 | 교정 | **자동 점검 스크립트**(아래 3절) — 기계가 잡는 오류 | 점검 리포트 | 스크립트 |
| 4 | 교열 | 다른 대화/다른 AI의 별도 검수 + 학생 역할 풀이 | `ai_review` | 별도 AI |
| 5 | 감수 | 선생님이 읽고 확정 (체크리스트) | `final` | 선생님 |
| 6 | 시쇄 | 소수 학생이 실제로 풂 → **문항 분석** | 정답률·오답 보기 선택률 | 학생 + 시스템 |
| 7 | 출판·개정 | 정식 공개, 오류 신고 → 개정 이력 | 버전 | 선생님/관리자 |

## 2. 개념 명세서 (단계 1, 가장 중요)
레벨별 칸을 만들기 전에 개념당 한 장을 먼저 확정한다. 이후 5개 레벨이 전부 이 장에서 파생된다.
- **핵심 규칙 세트**: 번호 붙은 규칙 목록. 레벨이 달라도 이 규칙과 어긋나면 안 됨(사실 고정).
- **커버리지 표**: `GRAMMAR_EXAMPLE_RULES.md`의 표 형식. 규칙 항목마다 필요한 예문 그룹, 비교쌍, 틀린 예.
- **흔한 오류 목록**: 내신 빈출 + 학생 실수. 오답 보기와 `wrong` 예문의 출처.
- **대비 개념·선행 개념**: 이미 DB에 `contrast` 링크가 있음. 선행 개념 링크는 보강.
- **교재 단원 대응**: 이미 DB에 있음(유닛 ↔ 개념).
- **레벨별 노출 범위**: 어느 레벨에서 어떤 규칙까지 가르치는지(예: L1은 규칙 1~2만).
저장: 파일(`docs/grammar-specs/<개념키>.md`)로 두고, 필요하면 나중에 DB로 옮김.

## 3. 자동 점검 스크립트 (단계 3, 먼저 만들 것)
사람/AI가 놓치는 기계적 오류를 칸 저장·확정 전에 걸러낸다. 확정 버튼 앞에 연결.
- 형식: 기존 `validateGrammarLesson`(이미 있음).
- **빈칸 정답 노출**: `sentence`/`text`에 정답 단어가 그대로 있는지, `___`가 한 곳인지.
- **정답 분포**: 문제 정답 위치 A~D 쏠림(개수 세기 제외), 비율 임계치.
- **정답 유일성(기계 가능분)**: `drillFix.wrong`이 문장에 정확히 한 번 있는지, `correct`가 `wrong`과 같지 않은지.
- **중복**: 같은 문장·거의 같은 문장이 설명/예문/빈칸/문제에 반복되는지(설명에서 본 문장을 빈칸으로 재사용 금지).
- **레벨 적합성(수치)**: 예문 단어 수가 레벨 범위(L1 4~7 … L5 15+)를 벗어나는 비율, 모르는 어휘 수준(어휘 목록 준비 시).
- **번역 누락**: `ko` 빈 값, 문제 보기 `ko` 누락.
- **분량**: 설명 항목당 예문 3개 이상, 그룹 수, 문제 수가 레벨 목표치와 맞는지.
- **교재 대응**: 해당 개념의 단원 제목 키워드가 설명/예문에 다뤄졌는지(경고 수준).
출력: 칸마다 `오류(막음)` / `경고(확인)` 목록. 화면에 표시하고, 오류가 있으면 확정 불가.

## 4. 시험 (단계 6) — "시험 인쇄" 단계
1. **AI 학생 시험**: 레벨별 학생 역할로 문제를 풀게 해서, 정답이 둘이거나 정답이 보이는 문항을 잡는다(별도 패스).
2. **선생님 통독**: 감수 체크리스트(`GRAMMAR_EXAMPLE_RULES.md` 5절 + 아래 추가)로 한 번 읽고 확정.
3. **소수 실사용**: 파일럿 개념은 학생 3~5명(레벨 해당)에게 실제로 배정해 푼다.
4. **문항 분석**: 정답률이 너무 높음(>95%)/너무 낮음(<30%)인 문항, 한 오답 보기에 쏠린 문항을 표시 → 개정 후보. (`grammar_responses`가 이미 있음 — 학생 풀이 기록이 연결되면 가능)
5. 합격 기준 예: 자동 점검 오류 0, 교열 high 0, 선생님 체크리스트 통과, 파일럿 학생 이해 질문 없음.

## 5. 파일럿 → 본작업
- **파일럿**: 개념 1~2개 × 레벨 3개(예: `sentence-patterns-123` L1~L3)로 전 공정 0~6단계를 끝까지 돈다. 목적은 콘텐츠가 아니라 **공정과 기준서를 검증**하는 것. 기준서·점검 스크립트·프롬프트를 여기서 고친다.
- **본작업**: 난이도순(difficulty_rank) 챕터 단위 배치. 한 배치 = 한 챕터의 개념들 × 필수 레벨. 배치마다 같은 공정.
- **한도 관리**: 구독 사용 한도 안에서 세션당 몇 칸씩. 칸 하나가 출력 3만~4만 토큰이라 세션당 3~5칸 정도로 예상(실측 후 조정).
- **API 자동 생성**은 꺼둠(`GRAMMAR_ENGINE_AI`). 비용이 확정되기 전에는 켜지 않음.

## 6. 추가로 필요한 시스템 (순서대로)
1. 자동 점검 스크립트 + 칸 화면에 점검 결과 표시, 오류 시 확정 막기.
2. 개념 명세서 형식 + 첫 명세서.
3. 파일 → DB 가져오기 스크립트(원고를 파일로 쓰고 초안으로 넣음).
4. 레슨 개정 이력(현재 덮어쓰기). 확정본 수정은 새 버전으로 남기기.
5. 학생 화면(레벨에 맞는 레슨 노출)과 오류 신고 버튼.
6. 문항 분석 화면(풀이 기록 연결 후).

## 7. 정해야 할 것
1. 편집 기준서 확정 방식: Claude가 초안을 쓰고 사용자가 고치는 방식으로 진행해도 되는가.
2. 감수 권한: 선생님이 확정 가능한가, 관리자만 가능한가.
3. 파일럿 대상 개념과 레벨, 파일럿 학생 확보 가능 여부.
4. 레벨별 어휘 기준 자료(학년별 필수 어휘 목록)가 있는가. 없으면 기준을 문장 길이 + 교과서 어휘로 단순화.
5. 외부 AI 사용 시 어느 서비스를 쓸 것인가(프롬프트는 서비스 무관).
