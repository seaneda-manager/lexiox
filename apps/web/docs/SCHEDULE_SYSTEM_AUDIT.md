# 스케줄 시스템 현황 조사 (2026-11-16, 0단계)

목적: 정규 / 내신 / 시험기간 hold 를 "칼같이" 지키는 시스템을 만들기 전에, 지금 어떻게 되어 있는지 사실만 정리한다.
이 문서는 조사 결과이며 코드·DB 는 바꾸지 않았다. (조사 시점 운영 DB 기준)

## 1. 한 줄 결론

hold(시험기간 보류)를 하는 장치는 **이미 만들어져 있지만 한 번도 작동한 적이 없다.** 입력 데이터가 비어 있고, 학생을 가리키는 ID 체계가 둘로 갈라져 있으며, 문법은 hold 대상에서 빠져 있다.

## 2. 스케줄(플랜) 종류와 상태

| 영역 | 테이블 | 학생 ID 기준 | hold 대상? | 운영 DB 행 수 |
|---|---|---|---|---|
| 단어 | `student_vocab_plans` | `academy_students.id` | O | 16 |
| 숙제(교재) | `student_homework_plans` | `auth.users.id` | O | 0 |
| 문법(신규, 개념 엔진) | `student_grammar_concept_plans` + `…_assignments` | `auth.users.id` (profiles) | **X** | 3 |
| 문법(구) | `student_grammar_plans` | (미확인) | **X** | 1 |
| 문법 2026(TOEFL) | grammar-2026 plans | (미확인) | **X** | - |
| 학생 개인 플래너 | `student_routine_slots`, `student_exams` | `academy_students.id` | - | 0 / 7 |

- 플랜마다 정지(`is_paused`)·재개·날짜 재배치 규칙이 따로 구현되어 있다. 공통 규칙이 없다.
- 문법 개념 플랜은 `UNIQUE(student_id)` 라 학생당 1개뿐이다. 정규와 내신을 나눌 수 없다.

## 3. 시험기간 데이터가 3곳에 있다

| 소스 | 내용 | 현재 데이터 |
|---|---|---|
| `school_exam_periods` | 학교별 시험일 + `prep_start_date` (관리자 수동 입력) | 0건 |
| `student_exams` | 학생별 시험 일정 (학생 입력/선생님 입력/자동수입) | 7건 |
| `naesin_exam_schedule` | 내신 시험 일정 | 0건 |

- hold 장치(`lib/examMode/applyExamMode.ts`, 크론 `/api/cron/exam-mode-check` 매일 00:00 UTC)는 **`school_exam_periods` 만** 읽는다.
- 그런데 그 테이블이 비어 있다. 실제로 쓰고 있는 시험 일정은 `student_exams` 7건뿐이고, hold 장치는 이를 모른다.
- 따라서 지금까지 hold 가 자동으로 걸린 적이 없다(`exam_mode_requests` 0건).

## 4. 학교 정보

- `schools` 테이블 0건. `academy_students.school_id` 가 채워진 학생 0명.
- 학교는 자유 텍스트(`academy_students.school`)로만 있고 표기가 제각각이다. 예: "미술고", "서울미술고", "서울미술고등학교" (같은 학교로 보이는 3가지 표기).
- 학교가 비어 있는 학생이 있다: 김태윤, 김태언, 김태언01, 유주원.
- 따라서 "같은 학교·학년 학생에게 동일 배정"을 하려면 학교 정규화가 먼저 필요하다.

## 5. 학생 ID 가 두 갈래

- 단어 플랜 16건은 모두 `academy_students.id` 를 쓴다(프로필 ID 와 일치 0건).
- 문법 개념 플랜 3건은 모두 `profiles.id`(auth) 를 쓴다(academy 와 일치 0건).
- `academy_students` 의 `id` 는 `auth_user_id` / `profile_id` 와 **서로 다른 값**이다(15명 전원).
- hold 코드는 학교 학생을 `academy_students.id` 로 찾은 뒤, 그 ID 로 `student_homework_plans`(auth 기준)를 갱신한다. ID 체계가 달라서 **숙제 플랜에 hold 가 걸리지 않는다.** 지금은 숙제 플랜이 0건이라 드러나지 않았을 뿐이다.
- 문법 플랜을 hold 에 넣으려면 `academy_students.id` ↔ `auth_user_id` 변환이 필요하다.

## 6. 학년 데이터 품질

- 김태윤은 M3, 김태언은 M2 로 저장되어 있다. 운영상은 같은 학년이다. 학년이 해가 바뀌어도 자동으로 갱신되지 않아 학년 값이 서로 다른 형식("M2", "중3", "3학년", "고1")으로 섞여 있다.
- `profiles.grade` 는 학생 20명 중 2명만 값이 있다.

## 7. 지금 학생 화면은 어떻게 판단하나

- 영역마다 자기 테이블만 본다. "오늘 이 학생이 할 일 전체"를 계산하는 한 곳이 없다.
- 단, `lib/assignments/studentAssignmentCalendar.ts` 가 배정을 모아 캘린더로 보여 주는 집계 헬퍼 역할을 하고 있다. 판정 함수를 둔다면 이 자리가 후보다.

## 8. 오늘 만든 임시 조치 (규칙이 아니라 수작업)

- 김태윤·김태언의 문법 배정을 시험 범위 4개 개념(11/16~19)으로 DB 에 직접 넣었다.
- 이 배정은 플랜과 연동되지 않는다. 스케줄 화면에서 "일정 다시 잡기"를 누르면 교재 순서 48개로 덮어쓴다.
- 두 학생은 같은 플랜 값이지만 서로 연동되지 않는다. 한쪽을 바꿔도 다른 쪽은 그대로다.

## 9. 확립해야 할 규칙 (초안 — 결정 필요)

1. **학생 식별**: 하나의 기준 ID 를 정한다(제안: `academy_students.id` 를 기준으로 두고 `auth_user_id` 로 연결, 또는 반대).
2. **학교 정규화**: `schools` 채우기 + `academy_students.school_id` 연결. 표기 통일은 사람이 확인.
3. **시험기간 단일 소스**: `school_exam_periods` 를 정본으로 하고, `student_exams` 는 학생 개인 예외로만 쓴다.
4. **우선순위**: 시험 당일·직전 > 내신 준비기간 > 정규 > 자율. 높은 층이 켜지면 낮은 층은 자동 보류, 끝나면 자동 재개.
5. **보류 방식 통일**: 보류 구간만큼 뒤로 미는 로직을 공통으로 쓴다(영역별 구현 금지).
6. **플랜 종류**: 정규 / 내신 두 종류를 학생당 하나씩. 내신은 시험 범위 개념 목록으로 지정.
7. **반 단위 배정**: 같은 학교·학년 학생에게 한 번에 배정하고, 학생별 예외만 따로 표시.
8. **어긋남 경고**: 범위 개념 미확정·일정 지연·학교 미입력·시험일 미입력 학생을 화면에 표시.

## 10. 확정된 정책 (2026-11-16 사용자 답변)

- **재개 방식**: 밀어서 이어가기. 보류된 기간만큼 정규 일정을 뒤로 밀어, 건너뛴 분량 없이 이어서 진행한다.
- **같은 학년의 기준**: 학교 + 학년. 같은 학교·같은 학년 학생은 한 묶음으로 똑같이 배정한다(수업반은 기준 아님).
- **내신 준비기간의 보류 대상**: 기본은 전부 보류(단어·숙제·정규 문법). 선생님이 학생(또는 영역)별로 예외(exception)를 만들 수 있다.
- **예외(exception)의 단위**: 영역별. 시험기간마다 영역(단어·숙제·정규 문법)별로 "보류 안 함"을 지정한다.
- **시험 범위(개념 목록) 입력 주체**: 원칙적으로 선생님. 단 super(admin)는 예외로 모든 학교·학생의 범위를 입력·수정할 수 있다.
