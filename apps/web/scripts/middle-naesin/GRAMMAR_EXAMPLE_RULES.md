# 중학내신 문법 레슨 · 예문/문제 생성 규칙

문법 레슨의 예문 모음(`exampleGroups`)과 문제(`questions`)를 만들 때 지키는 규칙이다.
사람이 만들 때도, AI(generate 기능)가 만들 때도 같은 규칙을 쓴다. (AI에게는 이 문서를 프롬프트에 그대로 넣는다.)

## 0. 기본 원칙 (사용자 지정)

1. **설명 속 모든 요소를 빠짐없이 다룬다.** 설명(rules)에 적힌 항목마다 예문이 최소 3개 있어야 한다.
2. **문법 요소를 이루는 모든 형태를 예문으로 보여 준다.** 형태가 여러 갈래이면 갈래마다 그룹을 만든다.
3. **비교가 필요한 것은 반드시 나란히 보여 준다.** (예: so ~ that vs such ~ that, used to vs would vs be used to, 주격 vs 목적격)
4. **틀린 예도 넣는다.** ✗ 표시 + 고친 형태 + 이유 한 줄.

## 1. 커버리지 표 (주제별 필수 그룹)

| 주제 | 반드시 있어야 하는 그룹 |
|---|---|
| 지각동사 | 동사마다 [원형 · v-ing · p.p.] 3문장 (see, watch, look at, hear, listen to, feel, smell, notice) · 원형 vs v-ing 의미 차이 · to부정사 ✗ |
| so ~ that | 일반동사 + so + 부사 · be + so + 형용사 · 일반동사 + so + many/much/few/little + 명사 · such + (a) + 형용사 + 명사 · so vs such 짝 · so ~ that(결과) vs so that(목적) · too ~ to / enough to 전환 · 틀린 예(so very 등) |
| 목적격 관계대명사 | 사람 who(m)/that · 사물 which/that · 사람+사물 함께이면 that · that 선호(the only, all…) · 목적어가 빠진 구조(___ 표시) · 전치사가 절 끝에 남는 경우 · 생략 전/후 · 주격 vs 목적격 · 틀린 예 |
| used to | 긍정(습관·상태) · didn't use to · never used to / used not to · Did ~ use to ~? · used to vs would · be used to + 명사/v-ing · used to + V vs be used to + V-ing vs be used to + V(쓰이다) · 틀린 예 |

새 주제를 만들 때는 먼저 **이 표 형태의 커버리지 표를 만들고**, 표의 칸을 모두 채운 뒤 문장을 쓴다.

## 2. 문장 규칙

- **한 문장에는 한 가지 포인트만.** 다른 문법이 섞여 학생이 헷갈리지 않게 한다.
- **중2 수준.** 한 문장 12단어 이내, 교과서·중학 필수 어휘 위주. 어려운 단어는 쓰지 않는다.
- **자연스러운 문장만.** 실제로 잘 쓰지 않는 조합은 만들지 않거나, 만들면 그룹 `note`에 "드물게 쓰임"이라고 밝힌다. (예: smell + p.p.)
- **최소 대비쌍.** 비교 예문은 같은 뼈대에서 한 요소만 바꾼다. (`I saw him cross…` / `I saw him crossing…`)
- **주제·주어·시제를 다양하게.** 학교, 취미, 음식, 날씨, 가족 등. 같은 동사·명사를 반복하지 않는다. 가능하면 해당 단원 본문의 어휘·주제를 섞는다.
- **부정문·의문문도 넣는다.** 긍정 예문만 늘리지 않는다.
- **`tag`** = 형태 이름(원형 / v-ing / p.p. / who / that …), **`note`** = 한 줄 이유. 태그는 학생이 형태를 눈으로 구분하도록 붙인다.
- **틀린 예(`wrong: true`)** 는 실제 내신 빈출 오류와 학생이 자주 하는 실수에서 뽑는다.
  (지각동사 + to, so very, so a + 명사, 관계대명사 뒤 목적어 중복, didn't used to, used to + v-ing …)

## 3. 한글 번역 규칙

- 직역이 아니라 **문법 포인트가 드러나는 자연스러운 번역**으로 쓴다. (`너무 ~해서 …했다`, `~하곤 했다`, `~에 익숙하다`)
- 원형/v-ing 차이처럼 뜻이 갈리는 짝은 번역에서 차이를 드러낸다. (`건너는 것을 봤다` / `건너고 있는 것을 봤다`)
- 틀린 예의 한글 칸에는 번역 대신 **고친 형태와 이유**를 쓴다.

## 4. 문제(questions) 규칙

- 주제당 **20~25문항**. 초급 : 중급 : 고급 ≈ 6 : 9 : 10.
- 유형 4종을 고르게: 틀린 문장 개수 / 맞는 문장 고르기 / 보기와 다른 것 / 이유 고르기.
- **문제문은 영어(중2 수준)**, 보기마다 한글 해석을 붙인다. (학생이 답을 고른 뒤 해석이 열린다)
- **오답 보기는 학생의 실제 오류에서** 만든다. 말도 안 되는 보기로 채우지 않는다.
- **정답 위치는 A~D에 고르게.** (개수 세기 문제는 1~4 순서 고정이라 제외)
- 난이도 기준: 초급 = 형태 확인 / 중급 = 오류 고치기·구별 / 고급 = 구문 전환, 헷갈리는 구문 구별, 여러 개 오류 개수 세기.
- 해설(`explanationKo`)은 왜 맞고 왜 틀린지를 한 줄로 쓴다.

## 5. 검수 체크리스트 (확정 전에 확인)

- [ ] 모든 예문이 문법적으로 맞다. (틀린 예만 ✗)
- [ ] 커버리지 표의 모든 칸에 예문이 있다.
- [ ] 같은 문장·같은 어휘가 반복되지 않는다.
- [ ] 정답이 하나뿐이다. (보기 중 정답이 둘이 되는 문제 없음)
- [ ] 정답 위치가 한쪽으로 쏠리지 않는다.
- [ ] 한글 번역이 자연스럽고 포인트를 드러낸다.
- [ ] AI가 만든 것은 **다른 패스**에서 문법·정답을 한 번 더 검증했다. (생성한 모델이 스스로 검수하지 않는다)
