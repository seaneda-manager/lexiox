# 통합 문법(Lexiox Gram) 설계안

상태: **초안 — 확정 대기**. 확정된 항목은 ✅, 제안값은 ◻︎ 로 표시한다.

## 1. 목표
- 문법 시스템을 **하나**로 합친다. 지금은 `grammar_2026_*`(Lexiox Gram, TOEFL 섹션)와 `jr_grammar_*`(Jr.)가 따로 있다.
- 같은 문법 개념을 한 번만 만들고, **프로그램(TOEFL / Hi-내신 / 중학 / Jr.)** 과 **목적**에 따라 설명·예문·문제만 바꿔 제공한다.
- 학습은 "설명 → 확인(관문) → 연습 → 실전"의 고정된 흐름으로 간다.

## 2. 학습 흐름 (챕터 1개) ✅
1. **개념 설명**: 핵심 개념 + 대표 예문 (예문은 프로그램/목적에 따라 달라짐)
2. **예외·주의**: 예외와 헷갈리는 경우
3. **표 정리**: 개념에 해당하는 단어·구조·어구를 표로 정리
4. **팝업 퀴즈 (관문)**: 설명 문장의 핵심 부분을 빈칸으로 → 전부 통과해야 다음 단계
5. **연습·드릴**
6. **실전 문제**

### 2.1 관문(팝업 퀴즈) 규칙 ✅
빈칸 한 개마다:
1. **주관식**으로 입력. 맞으면 **만점**, 다음 빈칸.
2. 틀리면 같은 빈칸이 **객관식**으로 전환.
3. 객관식에서 정답을 고르면 **통과(점수 없음)**.
4. 객관식에서 오답을 고르면 **정답을 보여 주고, 학생이 그 빈칸을 다시 직접 채운 뒤 감점하고 넘어간다.**
   - 감점은 기존에 쌓은 **Grammar point 총점**에서 뺀다. **0점 아래로는 내려가지 않는다.**
5. 모든 빈칸을 끝내야 다음 단계로 이동.

채점 세부:
- 주관식 허용 오차: 대소문자, 앞뒤 공백, 띄어쓰기 차이는 허용. 철자가 다르면 오답. ✅
- 정답이 둘 이상이면(`who`/`that` 등) **모두 정답**으로 등록한다. ✅
- 포인트는 포인트 시스템에 쌓는다(세부 점수표는 추후). ✅

### 2.2 재도전 규칙 ✅
- 관문에서 객관식 단계까지 간(= 주관식을 틀린) 챕터가 있으면 그 챕터는 **재도전 숙제**로 나간다.
- **챕터 전체를 처음부터 다시** 한다(틀린 빈칸만이 아님). 틀렸다는 것은 학습이 충분하지 않았다는 신호이기 때문.
- 기한: **숙제로 나간 날 안에** 한다. 하지 않으면 **벌칙으로 1회 추가** 재도전.
- 부모님 알림은 **나중에** 결정한다(연락처 구조는 아직 확인 안 함).

## 3. 변형(Variant) 모델
**유니버설 챕터**(개념 단위) 1개에 대해 **목적(대상 과정)** 과 **레벨** 조합으로 변형을 만든다.
목적에 따라 **설명 스타일, 예제 제시 방법, 팝업 퀴즈 문항, 드릴, 문제**가 달라진다. ✅

| 축 | 값 | 바뀌는 것 |
|---|---|---|
| 목적(대상 과정) | 중학-내신 / Hi-내신 / TOEFL, **추후 추가: Hi-수능, TEPS** (Jr.·일반 강좌는 추후 결정) | 설명 스타일, 예제 제시, 팝업 퀴즈, 드릴, 문제 |
| 레벨 | 기초 / 중간 / 심화 (교재 레벨이 결정) ◻︎ | 예문 난이도, 설명 어휘·길이, 다루는 포인트의 깊이 |

### 3.1 단계적 도입 — 1차 범위 ✅
변형은 한꺼번에 만들지 않고 **차례로** 늘린다. 목적별 방향:
- **중학-내신, Hi-내신**: **일반적인 문법 교재 형태**. 개념 설명 → 대표 예문 → 예외 → 표 정리 → 팝업 퀴즈 → 드릴 → 내신식 문제.
- **TOEFL**: **작문(writing)과 에세이 쓰기에 도움이 되는 형태**. 문법 규칙을 문장 쓰기·문장 결합·수정 연습으로 연결하고, 예문과 문제를 에세이 문맥에서 제시한다.
- **Hi-수능, TEPS**: 추후 추가 예정.
- **목적은 코드에 고정하지 않고 데이터(목록 테이블)로 둔다.** 목적을 추가할 때 코드 변경 없이 값만 늘리고, 그 목적의 변형을 만들면 된다. ✅
- 데이터 구조는 처음부터 목적×레벨을 담을 수 있게 두되, 1차에서는 위 값만 만들어 노출한다.
- 중학-내신과 Hi-내신은 같은 "문법 교재형"이지만 **레벨(예문 난이도·포인트 깊이)** 로 구분한다. 형태가 더 갈라져야 하면 그때 분리한다. ◻︎

- 설명 구조와 6단계 순서는 **모든 변형에서 공통**이다.
- 변형 생성: AI 초안 → 선생님 확인(Confirm) → 게시. 확정 전에는 학생에게 보이지 않는다.
- 학생은 자기 프로그램에 맞는 변형을 자동으로 본다. 메뉴 이름은 "문법" 하나로 합친다.

## 4. 데이터 구조 ◻︎
기존 테이블을 **지우지 않고** 확장/추가한다.

현재:
- `grammar_2026_units` (id, label_ko/en, level `'ms'|'hs'|'toefl'|'all'`, status)
- `grammar_2026_explanation_segments` (type `'text'|'animation'|'blank'`, content jsonb)
- `grammar_2026_drills`, `grammar_2026_stylistic_items`, `grammar_2026_student_responses`, `grammar_2026_unit_completions`
- Jr.: `jr_grammar_chapters(title, content text, level, topic_area)`, `jr_grammar_sessions`, `*_practice_logs`, `*_lesson_logs`

추가 제안:
- `grammar_chapters` — 유니버설 챕터(개념). `grammar_2026_units`를 이 역할로 승격하거나 연결.
- `grammar_chapter_variants` — (chapter_id, program, purpose, status[`draft`|`confirmed`|`published`]) 유일.
- 변형별 콘텐츠는 기존 `explanation_segments`/`drills`에 `variant_id`를 추가해 연결.
- `blank` 세그먼트의 content 형식:
  ```json
  { "text": "주어가 3인칭 단수면 동사에 ___를 붙인다",
    "answers": ["s", "es"],
    "options": ["s", "ed", "ing", "to"],
    "tolerance": "case_space" }
  ```
- `grammar_gate_attempts` — 빈칸별 시도 기록(주관식 정오, 객관식 정오, 감점 포인트, 시도 시각).
- `grammar_retake_assignments` — (student_id, chapter_id/variant_id, due_date, status, is_penalty). 기존 문법 스케줄(`student_grammar_plans`)과 같은 날짜 기준으로 숙제 목록에 합친다.

## 5. Jr. 이전 계획 ◻︎
- 새 구조를 먼저 만들고 기존 `jr_grammar_*`는 그대로 둔다.
- Jr. 챕터는 `title/content` 한 덩어리이므로, 새 구조의 Jr. 변형으로 옮길 때 설명/예문/빈칸으로 **다시 구조화**해야 한다(AI 초안 + 확인).
- 이전이 끝나면 사이드바의 Jr. 문법 메뉴를 없앤다. 학습 기록은 읽기용으로 보존한다.
- **열린 질문**: Jr. 챕터 목록이 Lexiox Gram과 같은가, 별도 커리큘럼인가?

## 6. 강의(칠판·음성)와의 연결
- 1~3단계가 강의 스크립트가 되고, 4단계 팝업 퀴즈가 강의 중간에 들어간다.
- 음성: 한국어 구간은 선생님 클론, 영어 구간은 영어로 분리 합성(적용됨).

## 7. 구현 순서 제안
1. 스키마(유니버설 챕터, 변형, 관문 시도 기록, 재도전 숙제).
2. 유니버설 챕터 초안·확정 화면.
3. 변형(프로그램×목적) 생성 + Confirm.
4. 관문 퀴즈 UI(주관식 → 객관식, 감점, 통과).
5. 재도전 숙제 생성 + 기한/벌칙(스케줄에 연결).
6. 칠판 강의 플레이어 + 음성.
7. Jr. 이전.

## 8. 미정 항목
- Jr. 챕터가 Lexiox Gram과 같은 목록인지.
- 1차 목적(문법 교재형 / TOEFL 작문형)의 설명 스타일, 팝업 퀴즈, 드릴, 문제 유형·양의 표. (TEPS 등은 이후)
- 포인트 점수표(만점/감점 값).
- 부모님 알림 수단과 연락처 구조.
- 재도전 "기한 내 미수행" 판정 시각(자정 기준 등).

## 9. 교재 목차 → 학습 연결 (선생님 배정 방식) ✅ 방향 확정, 세부는 ◻︎
교재 목차(`docs/grammar-toc/*.json`)를 앱 안으로 가져와, 선생님이 학생에게 교재와 진도를 배정하고 학생은 배정된 교재의 단원을 눌러 학습한다.

### 9.1 학생 화면
1. 문법 메뉴 → **선생님이 배정한 교재만** 카드로 보인다 (배정이 없으면 안내 문구).
2. 교재 → 챕터 아코디언 → 단원 목록 (히-내신 목록과 같은 접고 펴는 방식).
3. 단원 클릭 → 그 단원에 매핑된 **공통 개념 챕터의 학생 프로그램 변형**이 열린다 (6단계 흐름).
4. 단원별 진행 표시(완료/진행 중/미학습). 매핑·콘텐츠가 아직 없는 단원은 "준비 중".

### 9.2 선생님 화면
- 학생에게 **교재 배정**(교재, 시작 단원, 하루 진도). 기존 문법 스케줄(`student_grammar_plans`: 날짜↔챕터)과 같은 방식으로 단원 순서를 날짜에 배치한다.
- 교재별 **콘텐츠 제작 현황**(단원 ↔ 개념 챕터 ↔ 변형 확정 여부)을 보는 화면.

### 9.3 데이터 ◻︎
- `grammar_books`(title, level, source), `grammar_book_units`(book_id, chapter_no, chapter_title, unit_no, title, page, concept_id, point_id nullable, confidence). 콘텐츠 테이블에는 `book_id`가 없다(공유).
- `student_grammar_books`(student_id, book_id, assigned_by, start_unit, pace).
- 단원 진행은 기존 완료 기록(`grammar_2026_unit_completions`) 또는 새 단원 단위 기록에 연결.
- 목차 JSON은 초기 데이터로 가져오는 용도(관리자 가져오기 화면 또는 SQL).

### 9.3a 원칙: 내용은 하나, 교재는 목차·레벨만 다르다 ✅
- 설명·퀴즈·문제 같은 **콘텐츠는 교재가 아니라 (개념 × 레벨 × 목적) 변형 단위**로 만든다. 같은 레벨·목적의 변형은 어느 교재에서 들어와도 같은 내용이다. 교재마다 따로 만들지 않는다. (레벨·목적이 다르면 내용도 다르다.)
- 교재가 다른 것은 **목차(챕터·단원 구성과 순서)** 와 **레벨**뿐이다. 교재는 공통 콘텐츠를 다른 순서·묶음으로 보여 주는 "목차 보기"다.
- 따라서 교재 단원 → **공통 개념 챕터(+ 그 안의 소주제/포인트)** 로 연결한다. 한 교재 단원이 개념의 일부 포인트만 가리킬 수 있고(예: be동사 6단원 → be동사 개념의 포인트 하나씩), 여러 교재의 서로 다른 단원이 같은 개념을 가리킬 수 있다.
- 교재의 **레벨**이 변형의 레벨 축을 정하고, **목적**은 배정할 때 선생님이 정한다. (열린 질문: 학생의 프로그램과 교재 레벨이 다를 때 어느 쪽을 따를지)
- **진행(완료·점수)은 교재가 아니라 개념/포인트 단위로 쌓는다.** 교재가 바뀌어도 이미 통과한 내용은 다시 하지 않고, 교재 화면에는 그 진행이 그대로 표시된다.

### 9.4 순서 제안
유니버설 챕터·변형 스키마(1단계) → 교재 목차 가져오기 + 매핑 확정 → 선생님 배정 화면 → 학생 교재 화면 → 학습 연결.
